# Défi d'intégration 13.2 — Gestionnaire de prêts

## Contexte

Le département d'informatique prête du matériel aux étudiantes et étudiants : souris, casques, adaptateurs et câbles. Une application est nécessaire pour enregistrer les prêts et les retours.

## Besoins

Crée une application WinForms qui permet de :

- enregistrer un nouvel emprunt avec le nom de la personne, le matériel et la date prévue de retour ;
- afficher les prêts actifs ;
- marquer un prêt comme retourné ;
- empêcher qu'un même matériel soit prêté deux fois en même temps ;
- enregistrer ou retrouver les données dans un fichier ;
- afficher un résumé du nombre de prêts actifs et retournés.

## Contraintes

- Utilise une ou plusieurs classes pour représenter les données du problème.
- Organise l'interface graphique de façon claire.
- Valide les saisies et affiche des messages compréhensibles.
- Sépare autant que possible l'interface, les objets et la gestion des fichiers.
- Prévois une version minimale fonctionnelle avant d'ajouter les bonifications.

## Bonifications facultatives

- Rechercher les prêts d'une personne.
- Afficher les retours en retard.
- Permettre d'ajouter ou de retirer du matériel disponible.

## Critères de réussite

- L'application permet de gérer un cycle complet de prêt et de retour.
- Les objets et les fichiers sont utilisés de manière cohérente.
- Le projet est démontrable avec plusieurs prêts et plusieurs retours.

## Tests manuels et résultats attendus

1. Crée un prêt pour `Alex`, avec le matériel `Casque` et une date de retour future. **Résultat attendu :** le prêt apparaît dans les prêts actifs et le compteur de prêts actifs augmente de `1`.
2. Essaie de prêter le même casque à `Samira` avant le retour d'Alex. **Résultat attendu :** le programme refuse le deuxième prêt et conserve seulement le prêt d'Alex.
3. Enregistre le retour du casque d'Alex. **Résultat attendu :** le prêt passe dans les retours, le compteur de prêts actifs diminue et le casque redevient disponible.
4. Ferme puis redémarre l'application. **Résultat attendu :** les données enregistrées dans le fichier sont retrouvées et le prêt retourné conserve son état.
5. Crée plusieurs prêts. **Résultat attendu :** les compteurs de prêts actifs et retournés correspondent au nombre de lignes affichées.

Teste aussi une personne sans nom, un matériel non sélectionné et une date invalide. **Résultat attendu :** l'application affiche un message utile dans chaque cas et n'ajoute aucun prêt.
