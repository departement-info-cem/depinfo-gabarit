# Défi d'intégration 13.2 — Gestionnaire de prêts

## Contexte

Le département d'informatique prête du matériel aux étudiantes et étudiants : souris, casques, adaptateurs et câbles. Chaque exemplaire possède un nom ou un numéro unique. Une application est nécessaire pour enregistrer les prêts et les retours.

Un prêt contient au minimum le nom de la personne, l'identification unique du matériel et la date prévue du retour. Pour la version de base, la date peut être saisie sous forme de texte; elle doit simplement être présente, sans que tu aies à la convertir en objet date.

## Besoins

Crée une application WinForms qui permet de :

- enregistrer un nouvel emprunt avec le nom de la personne, l'identification du matériel et la date prévue de retour ;
- afficher les prêts actifs ;
- marquer un prêt comme retourné ;
- empêcher qu'un même exemplaire de matériel soit prêté deux fois en même temps ;
- enregistrer ou retrouver les données dans un fichier ;
- afficher un résumé du nombre de prêts actifs et retournés.

## Valeurs à utiliser

Le nom de la personne est un texte non vide. Le matériel est choisi dans un `ComboBox` qui contient exactement `CASQUE-01`, `SOURIS-01`, `ADAPT-01` et `CABLE-01`. La date de retour est un texte non vide au format `AAAA-MM-JJ`, par exemple `2026-09-15`; il n'est pas nécessaire de convertir cette date dans la version de base.

## Notions à utiliser

- une classe simple pour représenter un prêt;
- contrôles WinForms, notamment `TextBox`, `ListBox`, `ComboBox` et `Button`;
- lecture et écriture de fichiers texte déjà vues;
- événements des contrôles et conditions de validation.

## Contraintes

- Utilise une classe `Pret` pour représenter les données du problème; une seule classe suffit pour la version de base.
- Organise l'interface graphique de façon claire.
- Valide les saisies et affiche des messages compréhensibles.
- Crée des méthodes distinctes pour ajouter un prêt, enregistrer les données et les charger à l'ouverture.
- Prévois une version minimale fonctionnelle avant d'ajouter les bonifications.

## Exemple de résultat

**Entrées saisies :** nom `Alex`, matériel `CASQUE-01` et date de retour `2026-09-15`.

```text
Prêt ajouté : Alex — Casque — retour prévu le 2026-09-15
Prêts actifs : 1
Prêts retournés : 0
```

## Bonifications facultatives

- Rechercher les prêts d'une personne.
- Afficher les retours en retard.
- Permettre d'ajouter ou de retirer du matériel disponible.

## Critères de réussite

- L'application permet de gérer un cycle complet de prêt et de retour.
- Les objets et les fichiers sont utilisés de manière cohérente.
- Le projet est démontrable avec plusieurs prêts et plusieurs retours.

## Tests manuels et résultats attendus

1. Crée un prêt pour `Alex`, avec le matériel `CASQUE-01` et une date de retour future. **Résultat attendu :** le prêt apparaît dans les prêts actifs et le compteur de prêts actifs augmente de `1`.
2. Essaie de prêter le même `CASQUE-01` à `Samira` avant le retour d'Alex. **Résultat attendu :** le programme refuse le deuxième prêt et conserve seulement le prêt d'Alex.
3. Enregistre le retour du `CASQUE-01` d'Alex. **Résultat attendu :** le prêt passe dans les retours, le compteur de prêts actifs diminue et le `CASQUE-01` redevient disponible.
4. Ferme puis redémarre l'application. **Résultat attendu :** les données enregistrées dans le fichier sont retrouvées et le prêt retourné conserve son état.
5. Crée plusieurs prêts. **Résultat attendu :** les compteurs de prêts actifs et retournés correspondent au nombre de lignes affichées.

Teste aussi une personne sans nom, un matériel non sélectionné et une date non saisie. **Résultat attendu :** l'application affiche un message utile dans chaque cas et n'ajoute aucun prêt.
